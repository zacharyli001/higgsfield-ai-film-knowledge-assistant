# Higgsfield AI 影视知识助手 3.10.3

## Apple 本地英文识别

双击 `安装Apple本地语音.command`，按系统提示允许语音识别。重新加载扩展后，在设置页选择“Apple 本地识别”并点击“检测 Apple 本地识别”。音频只在本机听写，之后仅把英文短句交给当前翻译接口或 DeepL。

## 能做什么

- 全页保留英文，并在原文下方显示简体中文。
- 专门识别 `pre`、`code` 和常见代码高亮容器，整块翻译提示词；不会因为语法高亮把一句提示拆成零散单词。
- 支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini generateContent 和 Ollama Chat 五类协议。
- 内置 OpenRouter、DeepSeek、OpenAI、Anthropic、Gemini、Qwen、SiliconFlow、Moonshot、Groq、Mistral、Ollama 预设，并支持自定义兼容接口。
- 支持专有名词库，固定人物、镜头、模型、资产标签等译法。
- 在 Higgsfield Community Project 页面提供 AI 助手：快速提炼、工作流还原、TapNow 迁移和针对当前项目提问。
- 可将分析保存为浏览器本地知识卡，或导出 Markdown / JSON。
- 动态监听页面切换、弹窗和展开内容。项目说明、菜单、评论、按钮提示和开放的 Shadow DOM 都会继续扫描。
- 可切换“中英对照 / 仅中文 / 仅原文”。
- 默认启用全局强制翻译，扫描当前 DOM 中所有英文并持续处理动态加载内容。
- AI 译文按模型、接口和术语库保存在 Chrome 本地缓存中，相同内容优先复用。

## 安装或更新

1. 解压 `higgsfield-film-knowledge-assistant-v3.10.3.zip`。
2. 在 Chrome 地址栏输入 `chrome://extensions`。
3. 开启右上角“开发者模式”。
4. 首次安装：点击“加载已解压的扩展程序”，选择解压后的 `higgsfield-zh` 文件夹。
5. 如果已经安装旧版：用新版文件夹替换旧文件夹，然后在扩展卡片上点击刷新按钮。
6. 刷新已经打开的 Higgsfield 页面。

## 配置第三方 AI

1. 点击 Chrome 工具栏里的“Higgsfield AI 影视知识助手”，打开设置页。
2. 显示模式选择“中英对照”，翻译引擎选择“第三方 AI”。
3. 选择服务商。OpenRouter 适合用一个 Key 调用多家模型；也可直接选择 DeepSeek、OpenAI、Anthropic、Gemini、Qwen、SiliconFlow、Moonshot、Groq、Mistral 或本机 Ollama。
4. 预设会自动填写 API 协议、接口地址和示例模型。模型名可能随服务商更新，请按账户实际可用模型修改。
5. 填写自己的 API Key，点击“测试 API”。本机 Ollama 可以不填 Key。
6. 测试成功后点击“保存设置”。Chrome 会请求访问该 API 域名；只需允许你实际填写的域名。
7. 回到 Higgsfield，点击右下角“重新翻译”。

AI 请求使用 JSON 输出，并按总字数合并批次。硅基流动翻译默认关闭推理模式，避免把 Token 消耗在思维链上。长提示词会自动拆段，批量结果不完整时会缩小批次补译。

## 使用 Higgsfield Community 项目助手

1. 打开 Higgsfield 网站内部 Community 的任意 Project 页面。
2. 点击右下角“AI 项目助手”。
3. “快速提炼”优先读取 About the project，给出故事、视觉、工具和最值得吸收的方法。
4. “工作流还原”将公开内容整理为前期、生成、连续性控制、后期和交付步骤。
5. “迁移到 TapNow”抽象平台无关能力，并列出需要在 TapNow 中寻找、替代或验证的功能，不会臆造 TapNow 能力。
6. 可针对当前 Project 提问，例如“如何保持角色一致性”“哪些提示词结构可以复用”。
7. 结果可保存为浏览器本地知识卡，或复制、导出 Markdown / JSON。

助手会提取当前 Project 的公开可见文本，重点包括 About the project、工具、提示词、制作阶段、问题与解决办法。原文没有说明的内容会放入“待验证信息”。

## 加载专有名词库

设置页的术语库每行一条：

```text
Higgsfield = Higgsfield
BREATHING HANDHELD = 呼吸感手持摄影
dolly-in = 推轨靠近
negative fill = 负补光
@char_CB_Cal = @char_CB_Cal
```

左右相同表示保护原词。支持：

- TXT：直接使用上述逐行格式，也接受 `英文 => 中文` 或制表符分隔。
- JSON 对象：`{"dolly-in":"推轨靠近"}`。
- JSON 数组：`[["dolly-in","推轨靠近"]]`，或 `[{"source":"dolly-in","target":"推轨靠近"}]`。

导入后需要点击“保存术语库”。修改术语库会清除当前页面的内存译文，并按新术语重新翻译。扩展也能导出 TXT 备份。

安装包内附带 `影视AIGC专业术语库.txt`，包含影视开发、摄影机运动、镜头与曝光、灯光、美术、剪辑、调色、视效、声音、AIGC 视频、一致性排错和提示词标签等分类，可直接在设置页导入。以 `#` 开头的分类说明不会进入术语表。

## 提示词区域的处理

像截图中的 `OPTICS`、`CAMERA`、`LIGHTING`、`MOVEMENT NOTE`、`REFERENCES` 代码块，会保留带颜色的英文原文，并在整个代码块下方增加等宽中文译文。默认保留大写控制标签，同时给出中文释义；`@角色`、文件名、数字、镜头焦段、宽高比和型号会被保留。

如果某个提示词容器没有被识别，点击页面右下角“重新翻译”。仍未识别时，可把该区域的 HTML 结构或新截图发来继续补充选择器。

## Chrome 本地翻译

没有第三方 API 时，可以在设置页启动 Chrome 本地翻译。它不发送网页文字，但术语遵循和长段落连贯性通常弱于 AI。首次使用需要下载语言包，且必须保留设置页标签。

## 隐私与费用

- AI 模式会把待翻译的网页文字和当前术语表发送给你选择的第三方 API。请不要翻译包含不希望发送给该服务商的私密内容。
- API Key 保存在本机 Chrome 扩展存储中，不注入网页，不写入导出的术语库。只有扩展后台向你授权的 API 域名发起请求。
- 扩展不会读取 Cookie、密码或浏览历史。用户输入框、文本框和可编辑区域不会翻译或上传。
- 第三方 API 可能产生费用，具体由服务商、模型和文本量决定。页面首次完整翻译会产生较多请求；同一页面会使用内存缓存，刷新页面后需要重新翻译。

## 已知限制

- 图片和视频画面里的文字不做 OCR，因此不会翻译。
- 关闭的 Shadow DOM、跨域播放器内部文字和 CSS 伪元素可能无法访问。
- 中英对照会增加页面高度；导航栏和小按钮使用紧凑行内译文，长段落和提示词使用块状译文。
- 自定义接口需要符合所选的五类协议之一。模型若不支持原生 JSON，扩展会依靠提示词解析 JSON；输出稳定性取决于模型能力。
- 需要 AWS SigV4、Google Cloud OAuth、企业代理签名等专用鉴权的直连服务，应先通过对应网关转成上述五类协议；普通 API Key 和 Bearer Token 接口可直接配置。

接口实现参考：[OpenAI API 官方文档](https://developers.openai.com/api/reference/)、[Anthropic Messages](https://docs.anthropic.com/en/api/messages)、[Gemini generateContent](https://ai.google.dev/api/generate-content)、[Ollama Chat](https://docs.ollama.com/api/chat) 和 [OpenRouter](https://openrouter.ai/docs/quickstart)。
